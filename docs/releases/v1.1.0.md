# MacroCode v1.1.0 — Release Notes

**Date:** November 27, 2026
**Previous Version:** v1.0.1

---

## 🎯 Overview

v1.1.0 is a feature and hardening release. Sessions can now be archived and
restored instead of being destroyed, conversations can stream in parallel, and
a performance instrumentations framework (`/perf`) is included. Several
security findings from the 2026-11 audit (B1–B4 and B6) are fixed, together with
Rust-side and UI performance work that keeps the terminal responsive during
long streaming responses.

## ✨ Added

- **Session history:** the sidebar's delete action now moves a session to the
  archive (`Session.deletedAt`). A new searchable/filterable history dialog
  lists active and archived sessions, restores them, or permanently deletes an
  archived session after confirmation. Archived sessions are hidden from the
  sidebar, search and F2/Ctrl+Tab navigation, can never become active, and are
  never activated when restored from a backup. `deletedAt` survives JSON backup
  roundtrips.
- **Parallel conversations:** streaming state and abort controllers are tracked
  per session. Starting or stopping one conversation no longer blocks or
  cancels another; the "typing" caret is shown only in the session that is
  actually streaming.
- **`/perf [on|off|reset]`:** a performance report covering boot, store
  updates, deferred persistence, SQLite saves, streaming frames, long tasks,
  terminal render time and JS heap. Measurements are on by default in dev
  builds and opt-in (`/perf on` or `localStorage macrocode-perf=1`) in releases.
- **Terminal rendering experiment:** views with 120+ lines opt into
  `content-visibility: auto` (`cv on` in the `terminal:` report line). Set
  `localStorage macrocode-cv=0` and restart to disable the experiment.
- **Session summaries store:** narrow derived state for sidebar listing so
  streaming token updates do not re-render the whole sidebar.

## 🔒 Security

- **B1:** `apply_patch` / `undo_patch` no longer write through predictable temp
  paths; symlinked temp targets are rejected before write/copy, closing an
  arbitrary-write path outside the workspace.
- **B2:** exec file arguments are canonicalized (with parent fallback for
  not-yet-existing paths) before the workspace jail check, and `eslint` / `tsc`
  are subject to the same file-argument jail in both Rust and the frontend
  policy.
- **B3:** the proxy SSRF guard now unwraps IPv4-mapped, NAT64 and 6to4 IPv6
  addresses and blocks ULA, site-local, multicast and unspecified IPv6 ranges.
- **B4:** Git remote names are validated before being passed to `git push`; the
  branch read from `.git/HEAD` is validated and pushed as an explicit
  `HEAD:refs/heads/<branch>` refspec after `--`. `git switch` also uses `--`.
  A new `E_INVALID_REMOTE` error is localized in all five UI languages.
- **B6:** snapshot manifest `id` and `files` are validated so a crafted backup
  cannot delete `.macrocode` or empty the workspace on restore.

## ⚡ Performance

- Streaming text/reasoning deltas are batched into 40 ms windows instead of
  writing to the store on every token; pending deltas are flushed before usage
  writes, cleanup and errors so no final text is lost.
- `localStorage` session serialization is deferred; SQLite stays the primary
  store and localStorage is a shutdown/backup safety net.
- Timeline computation is split into a cached message skeleton and a light
  merge step; view lines are cached and scrolling is coalesced into one rAF per
  frame. Markdown re-parsing delay adapts to long streaming answers.
- App, Sidebar and StatusBar subscribe to narrow state slices and memoized
  callbacks; token updates no longer re-render the whole UI tree.
- Rust: blocking file work runs on `spawn_blocking`, exec capture writes use
  `tokio::fs` with a 1 MiB per-stream cap (the pipe is still drained), reqwest
  clients are reused, keychain providers are read in parallel, and legacy key
  migration no longer blocks the UI thread. Release builds use thin LTO and
  symbol stripping.

## ⬆️ Upgrading

Update in place from 1.0.1 using the in-app updater or download a package from
the [releases page](https://github.com/Geblkc/MacroCode/releases/latest).
Sessions, settings and OS keychain entries are preserved. Sessions archived in
this release remain in the history dialog and can be restored at any time.

## 📝 Notes

- Linux packages are built for x86_64.
- The `content-visibility` experiment depends on WebView support; if the
  renderer ignores it, behavior is unchanged and only the `cv off` report line
  differs.
- Audit items B5 (renderer trust boundary / capabilities), B7 (plaintext input
  history in localStorage) and B8 (hardening notes) are deliberately deferred
  to a later maintenance release.
- Report security issues privately via GitHub Security Advisories; see
  [`SECURITY.md`](../../SECURITY.md).
