# MacroCode v1.2.0 — Release Notes

**Date:** November 28, 2026
**Previous Version:** v1.1.0

---

## 🎯 Overview

v1.2.0 hardens the build / plan / ask agent modes. A restored run now keeps the
mode it was created in, approvals are re-validated against mode restrictions,
mode switches are locked while an approval is pending, and persisted modes are
validated from a single source of truth. Subagents are genuinely read-only and
plan step IDs stay stable across calls and restarts.

## ✨ Added / Changed

- `/mode [m]`, `/build`, `/plan` and `/ask` are now handled in the pure command
  layer (`handleSlashCommand`) via `parseAgentModeCommand` and `agentModeLabel`.
  `CommandContext` injects the mode accessors so the command module stays
  UI-independent.
- The pending-approval lock applies to both the ModeSelector and `/mode`: while
  an approval card is waiting, the mode cannot be changed. Restored runs are
  marked as streaming so the stop control and the lock stay consistent.
- Agent mode validation is centralized in `agentModes.ts` (`AGENT_MODES`,
  `isValidAgentMode`, `normalizeAgentMode`). Unknown modes loaded from SQLite,
  localStorage or JSON backups fall back to the safe **`plan`** mode instead of
  silently enabling the full Build tool set.
- Read-only, planning and ask tool lists are derived from one source; the deny
  list is deduplicated with a `Set`.
- Subagents use an `ask`-filtered tool schema, a dedicated read-only prompt
  (the coordinator's mode instructions are stripped), and
  `create_snapshot` / `plan` / `todo` are denied.
- Plan step IDs are derived from the tool call ID, so a second `plan` call no
  longer collides with earlier steps and completes the wrong todo item.
- Architecture and development-log documentation updated for the new command
  and mode flow; the README description was revised.

## ⬆️ Upgrading

Update in place from 1.1.0 using the in-app updater or download a package from
the [releases page](https://github.com/Geblkc/MacroCode/releases/latest).
Sessions, settings and OS keychain entries are preserved. Previously stored
unknown mode values are normalized to `plan` on load.
